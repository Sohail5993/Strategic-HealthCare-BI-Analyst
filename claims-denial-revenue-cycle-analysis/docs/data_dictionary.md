# Data Dictionary — `data/claims.csv` / `fact_claims`

One row = one claim, as of its first submission, tracked through to final
adjudication (payment or write-off).

| Field | Type | Description |
|---|---|---|
| `claim_id` | string | Unique claim identifier, `CLM-######` |
| `patient_id` | string | Synthetic patient identifier, `PAT-#####` |
| `provider_id` | string | Rendering provider, `PROV-###` (60 providers) |
| `facility` | string | One of 4 facilities: Main Campus, North Clinic, South Clinic, East Medical Center |
| `payer_name` | string | One of 8 payers (Medicare, Medicaid, Aetna, UnitedHealthcare, Cigna, Blue Cross Blue Shield, Meridian Health Plan, Self-Pay) |
| `payer_type` | string | Government / Commercial / Managed Care / Self-Pay |
| `service_line` | string | One of 10 clinical service lines |
| `cpt_code` | string | Simplified procedure code, representative of the service line |
| `icd10_code` | string | Simplified diagnosis code, representative of the service line |
| `date_of_service` | date | Date care was delivered |
| `claim_submission_date` | date | Date the claim was first submitted to the payer |
| `billed_amount` | decimal | Gross charge submitted on the claim |
| `paid_amount` | decimal | Actual amount reimbursed (0 if never paid) |
| `is_clean_claim` | boolean | `TRUE` if the claim was paid on its very first submission with no denial |
| `first_pass_status` | string | `Paid` or `Denied` — outcome of the *first* submission attempt |
| `denial_reason_code` | string | CARC-style reason code (e.g. `CO-197`); null if not denied |
| `denial_reason_description` | string | Human-readable reason description |
| `denial_category` | string | Root-cause bucket: Authorization, Eligibility, Medical Necessity, Missing Information, Timely Filing, Duplicate Claim, Bundling, Coding Error, Contractual |
| `is_resubmitted` | boolean | Whether a denied claim was corrected and resubmitted / appealed |
| `resubmission_count` | integer | Number of resubmission/appeal cycles |
| `final_status` | string | `Paid`, `Denied - Written Off`, or `Pending Appeal` — the ultimate outcome |
| `turnaround_days` | integer | Days from submission to final adjudication |

## Denial reason codes used

| Code | Description | Category |
|---|---|---|
| CO-16  | Claim/service lacks information needed for adjudication | Missing Information |
| CO-18  | Duplicate claim/service | Duplicate Claim |
| CO-22  | Coordination of benefits / other payer responsible | Eligibility |
| CO-29  | Timely filing limit expired | Timely Filing |
| CO-50  | Non-covered service — not deemed a medical necessity | Medical Necessity |
| CO-97  | Benefit included in payment for another service | Bundling |
| CO-109 | Claim not covered by this payer/contractor | Eligibility |
| CO-11  | Diagnosis inconsistent with procedure | Coding Error |
| CO-197 | Precertification/authorization absent | Authorization |
| CO-45  | Charge exceeds fee schedule/contracted amount | Contractual |

These follow the real CMS Claim Adjustment Reason Code (CARC) format and
spirit; volumes and dollar amounts are entirely synthetic.

## Data notes / limitations

- This is a **synthetic** dataset generated by `scripts/generate_claims_data.py`
  with a fixed random seed (42) for reproducibility — it does not represent any
  real patient, provider, payer, or health system.
- A handful of "root causes" were deliberately embedded in the generation logic
  (see the docstring at the top of `generate_claims_data.py`) so the SQL/Tableau
  analysis has real signal to uncover — this mirrors how a real denial-management
  project would surface true operational issues, without using any real data.
- `paid_amount` reflects a blended payer-specific reimbursement ratio applied to
  `billed_amount`, so **Collection Rate here is a *gross* collection rate**
  (paid ÷ gross charges), not a net collection rate against contractually
  allowed amounts — worth calling out explicitly if presenting this metric,
  since "gross" and "net" collection rate are easy to conflate.

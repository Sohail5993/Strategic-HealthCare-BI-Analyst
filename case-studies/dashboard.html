Star Schema Redesign — Healthcare Model

The healthcare patient-encounters dataset rebuilt as a governed star schema: one fact table with an explicit grain, five conformed dimensions, and a bridge table resolving the one genuine many-to-many relationship in the model. Click any table below to trace its relationships.

Grain statement

FactEncounter is grained at one row per patient encounter. Every measure (length of stay, total cost, readmission flag) is true at that grain — nothing is pre-aggregated, so any report can roll it up to whatever level it needs.

Why SCD2 on Patient only

DimPatient is the one dimension where history genuinely matters — a patient's region or assigned provider changing over time affects which encounters should be attributed to which value at the time. The other dimensions (Provider, Date, Payer, Facility) change rarely enough that overwriting in place is the right call.

Why the bridge table

A single encounter can carry multiple diagnosis codes, and a diagnosis code applies to many encounters — a true many-to-many relationship. BridgeEncounterDiagnosis resolves it with a diagnosis rank (primary/secondary), which a single foreign key on the fact table couldn't represent.

Conformed dimensions

DimDate, DimPayer, and DimFacility are built once and shared — the same DimDate, for instance, would join equally well to a future claims or scheduling fact table, rather than every new fact table redefining its own copy of "what is a month."
